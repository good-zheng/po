脚本按职责分为两类：
- Bash 部署脚本（deploy-api.sh / deploy-chat.sh / deploy-redis.sh）：通过 `docker build` + `docker push` 将各服务镜像推送到腾讯 TCR（ccr.ccs.tencentyun.com），并通过 `USE_OFFICIAL_IMAGES` 切换国内加速镜像；所有脚本共享 REGISTRY/NAMESPACE/REPO/TAG/PLATFORM 环境变量约定，并在 push 后调用 `docker manifest inspect` 自证 tag 可解析。
- Node.js 运行包装器（*.mjs）：`run-service.mjs` 根据 service 参数分发到 api（Maven）、chat/agentcore/agentcooking（uvicorn + pytest，复用 chat/.venv）；`run-mobile.mjs` 负责 Expo/Android 构建，自动探测 ANDROID_HOME、注入 JAVA_HOME，并修补 Android SDK 自带的旧版 ninja 以支持长路径；`jdk.mjs` 提供 `resolveJdkHome()` 从 ~/.jdks 或 JAVA_HOME 定位 JDK 17；`run-sh.mjs` 在 Windows 上绕过 WSL bash stub 直接调用 Git Bash 执行任意 .sh。
依赖方向：run-service.mjs 与 run-mobile.mjs 共同依赖 jdk.mjs；Bash 脚本与 Node 脚本之间无相互引用，仅通过根 package.json 的 pnpm scripts 暴露统一入口。
