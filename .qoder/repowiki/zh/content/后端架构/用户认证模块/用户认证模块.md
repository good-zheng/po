## 简介
本文件为用户认证模块的安全架构文档，聚焦于基于JWT的令牌认证机制、用户注册与登录流程、密码加密存储策略、以及权限控制（RBAC）的设计与实现建议。文档同时提供完整的认证流程图与API调用示例，帮助读者理解并落地安全的用户认证与授权方案。

## 项目结构
认证相关代码集中在后端Java服务中，采用分层架构：
- 控制器层：对外暴露认证接口（登录、注册）
- 服务层：封装业务逻辑（校验、密码处理、令牌签发）
- 工具层：JWT生成与验证
- 数据模型：用户实体、请求/响应DTO
- 持久化：通过Repository访问数据库（由Spring Data JPA驱动）

## 架构总览
认证流程采用“无状态”的JWT模式：
- 注册：校验唯一性 -> 密码加密 -> 落库
- 登录：校验凭据 -> 签发JWT -> 返回令牌
- 鉴权：后续请求携带令牌，服务端解析并验证

```mermaid
sequenceDiagram
participant U as "客户端"
participant C as "认证控制器"
participant S as "认证服务"
participant R as "用户仓库"
participant J as "JWT工具"
U->>C : POST /auth/login (用户名, 密码)
C->>S : login(登录请求)
S->>R : 按用户名查询用户
R-->>S : 用户对象或空
S->>S : 校验密码(BCrypt)
S->>J : 生成JWT(含用户名、过期时间)
J-->>S : 令牌字符串
S-->>C : 登录响应(包含令牌)
C-->>U : 200 + {token, 用户信息}
```

### 认证服务（AuthServiceImpl）
- 职责：注册与登录的核心业务逻辑
- 注册流程：
  - 检查用户名唯一性
  - 使用BCrypt对密码进行加密存储
  - 保存用户并返回成功提示
- 登录流程：
  - 根据用户名获取用户
  - 使用BCrypt比对明文密码与密文
  - 校验通过后签发JWT并组装响应

## 性能与安全考量
- 密码加密：使用BCrypt，具备盐值与自适应成本，抗彩虹表与暴力破解
- 令牌安全：
  - 仅包含必要声明（如用户名），减少泄露面
  - 设置合理过期时间，配合刷新策略降低重放风险
  - 传输层强制HTTPS，防止中间人攻击
- 输入校验：使用JSR-303注解进行基础校验，结合服务端二次校验
- 错误信息：统一错误码与消息，避免泄露内部细节
- 扩展建议：
  - 增加IP白名单、设备指纹、验证码等风控措施
  - 引入令牌黑名单或短期短命令牌+刷新令牌机制
  - 对敏感操作增加二次确认

## 故障排查指南
- 登录失败：
  - 检查用户名是否存在、密码是否正确（BCrypt匹配）
  - 查看统一异常返回的错误码与消息
- 注册失败：
  - 用户名冲突会抛出异常，需确保唯一性
- 令牌问题：
  - 校验失败通常由签名错误或过期引起
  - 检查配置中的密钥与过期时间

## 结论
该认证模块以JWT为核心，实现了简洁高效的无状态认证。通过BCrypt保障密码安全，统一的控制器与服务层设计提升了可维护性与可扩展性。建议在现有基础上补充拦截器/过滤器以实现细粒度权限控制（RBAC），并引入刷新令牌与风控策略，进一步提升安全性与用户体验。

### 基于角色的访问控制（RBAC）实现建议
- 在JWT中嵌入角色信息（例如roles数组），或在服务端缓存用户角色映射
- 使用拦截器/过滤器在请求进入控制器前：
  - 解析并校验JWT
  - 提取用户身份与角色
  - 根据资源所需权限进行授权判断
- 在控制器或方法上使用注解标注所需角色，由拦截器统一处理
- 未通过校验的请求返回401/403，并通过统一错误格式返回
